簡報與實作追問

01. 你的哪一段經驗最符合 Lenovo ET&T 這個職缺？

The closest match is my Serviceability work at Dell. I worked with two types of data that a monitoring tool needs. We collected hardware information from iDRAC over Redfish and workload performance from vCenter CMS. I also worked on iDRAC event mapping and routing. At Amazon Alexa, I helped connect a web UI to backend APIs and display metrics. That gives me experience with both collecting platform data and presenting it to users.

02. 請完整走一次第 05 頁的 Redfish 收集流程。

We define the collection intervals in a Helm ConfigMap. When a scheduled job runs, it notifies Platform Service. Platform Service forwards the request to the Node Agent. The Node Agent translates the authentication context for the target iDRAC and then calls its Redfish API. The collection scripts format the results for the Dell backend. CPU, memory, and VM performance come from vCenter Cluster Monitor Statistics, which is a separate data source.

03. Redfish 和 vCenter 都有 CPU 相關資料。你們各拿什麼？

In our workflow, iDRAC Redfish gives us hardware information such as processor health, storage information, PSU health, fan speed, temperature readings, and firmware state. vCenter CMS gives us CPU, memory, and VM performance. For example, a processor can report healthy while vCenter shows high CPU usage. The first signal describes hardware health. The second tells us how much compute the workloads are using.

04. Node Agent 在認證流程中負責什麼？如果你來設計，會怎麼保護憑證？

In our flow, Platform Service forwards the collection request, and the Node Agent prepares the authentication context for the target iDRAC before making the Redfish call. For a new collector, I would keep BMC credentials on the service side, use an account with only the permissions needed for monitoring, and verify TLS certificates. If the client uses a Redfish session, I’d keep its token out of logs and handle session expiry explicitly.

面試官可能接著問你們實際用什麼 auth。簡報能確認的是 Node Agent 負責這一步。Basic Auth、session token 或其他機制，請以你們實際的做法回答。

05. 第 06 頁的 iDRAC event 跟定期收集 telemetry 有什麼差別？

Scheduled telemetry gives us a snapshot of hardware or workload state. The event flow handles a fault that has already been recorded. In our system, Platform Service wrote the iDRAC event to a fault list, and Event Manager checked that list for new records. It mapped the event to a payload with severity and device context, checked for duplicates using node, host, and component, and applied the throttling policy. The event went to vCenter and also to the Dell backend when reporting was required and enabled.

06. 四種 log collector 有一個失敗時，使用者會拿到什麼？

The main service dispatches the collection requests over gRPC, and the sidecars collect logs in parallel. Each collector reports its own result. If one fails, we record that failure in the database and package the successful sources into the ZIP. For example, if iDRAC log collection fails, the ESXi, vCenter, and microservice logs can still be included. Support can start investigating with the data that was collected.

07. NIM 如何判斷要不要更新韌體？如果送出更新後連線中斷，你會怎麼處理？

NIM starts with the installed hardware and firmware inventory. The hardware bundle catalog provides the target versions, and Dell System Upgrade CLI compares the two. When an update is needed, NIM uses Redfish to request it from iDRAC. If I were designing recovery for a connection loss after submission, I would check the existing job or task state before submitting another request. Once it completes, I would verify the installed firmware version against the target.

把實際做過的版本比較與更新請求，和你會怎麼設計中斷後的復原分開說明。如果被追問 endpoint，就回答你們實際呼叫的 action。

DMTF Redfish Asynchronous Operations

08. 映像檔複製從 2–3 小時降到約 30 分鐘。你實際改了什麼？

I changed how NIM transferred the installation image. The original flow copied the OVA from an image mounted through iDRAC. I added a file-share path over a high-speed NIC. Before copying, the workflow selects and configures the NIC and verifies connectivity to the file server. If validation fails, NIM reports the error and exits. The copy took around 30 minutes on the faster path, compared with about two to three hours on the original path. Those numbers refer to the image copy step and depend on network conditions.

Lenovo 監控工具與 JD 技術題

09. 你用過 iDRAC Redfish。如果目標換成 OpenBMC，哪些能沿用，哪些要重新驗證？

Redfish defines the management API, and OpenBMC’s bmcweb implements it. I would reuse the client logic for HTTP requests, resource discovery, and data normalization. I’d start at the Redfish service root and follow the resource links exposed by the device. Then I’d verify which resources and fields the target platform supports, especially anything that depended on Dell-specific extensions. I’d test the common fields on both platforms before adding vendor-specific handling.

10. 如果 iDRAC timeout，但 vCenter 仍顯示 CPU 使用率很高，Dashboard 應該怎麼顯示？

I would show the two signals independently. The hardware panel would show the last successful reading with its timestamp and mark it as stale or unavailable. If the vCenter sample is still fresh, I would continue showing the current CPU usage. That lets the operator see both what we know about the workload and when we last verified the hardware state. I would also track collection failures separately so we can tell whether the monitoring path itself is having a problem.

11. 如果要用 Go 每分鐘收集 1,000 台伺服器，你會怎麼設計？

I’d stagger the polling schedule so all 1,000 devices don’t receive requests at the same time. I’d feed the jobs into a bounded worker pool and put a deadline on each HTTP request using a Go context. I would also prevent overlapping polls for the same BMC. To tune the worker count, I’d measure queue delay, request latency, and how many collections finish within the polling interval. That gives us a way to increase throughput while keeping the load on each BMC predictable.

Go context · Go net/http

12. 如果用 Python 處理不同廠商回傳的 Redfish JSON，你會怎麼做？

I’d separate HTTP collection from parsing and normalization. The parser would map each response into a common record with a device ID, source, timestamp, status, and units where applicable. I’d keep a missing value distinct from a real zero. For example, a fan reading of zero RPM is different from a payload where the fan reading is absent. I’d test the parser with representative payloads from each platform, including partial responses and fields that are missing.

13. 你會怎麼設計監控工具的 REST API 和 Web UI？Alexa 的經驗怎麼用在這裡？

I’d expose a current health endpoint, such as GET /api/v1/nodes/{id}/health, and a separate metrics endpoint that accepts a time range. The health view would show component status, the data source, and the last successful collection time. The performance charts would show gaps when samples are missing. At Alexa, I helped connect a UI to backend APIs and turn response data into latency and token charts. I’d apply the same separation here. The backend defines what each metric means, and the UI makes it easy to interpret.

14. Cluster 顯示 256 GB RAM，是否代表一台 VM 可以使用分布在兩台 host 上的 256 GB？你會怎麼監控？

A cluster can report 256 GB of aggregate memory when two hosts each have 128 GB. A VM runs on one host at a time, so that aggregate figure does not describe the memory available to that individual VM. I’d show cluster capacity for planning, host-level usage for identifying resource pressure, and VM-level usage for finding the workload behind it. In vSphere, DRS can rebalance workloads by moving a VM to another host with vMotion.

15. 你怎麼測試這套監控工具，確定它在裝置故障時仍顯示正確資訊？

I’d start with an acceptance criterion. If Redfish times out while vCenter is still returning fresh data, the UI should show stale hardware health alongside current performance. I’d unit test parsing with sanitized payloads, then use a fake HTTP server to simulate timeouts, authentication failures, and malformed responses. I’d verify the result through the collector, API, and dashboard. Finally, I’d run the same checks against a lab BMC to confirm the behavior on real hardware.
