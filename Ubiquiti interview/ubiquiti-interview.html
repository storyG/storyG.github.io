Log bundle 可由 API 或 vCenter UI 觸發。Main service 透過 gRPC 派送工作，每種 log type 使用獨立 sidecar collector，讓 collector 更容易攜帶到不同產品。Sidecar 執行對應 script：ESXi、iDRAC、vCenter 使用既有 API；microservice logs 則透過我們的 API 向 pod 下 command。各來源平行收集、分資料夾存放，再打包成 ZIP。單一 collector 失敗會記錄在 DB，不影響其他收集；失敗項目不放入最終 bundle。

面試追問可補：gRPC 的 request/response schema、平行度／逾時設定、DB 記錄欄位、microservice command 的權限與安全控制。

04 · Dell / Serviceability 約 35 秒

Telemetry：排程、格式與重試

排程

收集頻率設定在 Helm ConfigMap；不同資料類型可使用不同週期，由 cron job 觸發對應 script。

資料

收集 hardware 資訊與狀態、performance 狀態及 events。

資料格式

Collection script 產出符合 Dell backend 接收格式的資料。

重試與封裝

失敗時採 exponential backoff，持續至下一個 cycle；持續失敗的項目不放入最終 archive。

口頭講稿

Telemetry 由 Helm ConfigMap 設定排程，不同系統資料可使用不同週期。收集內容包括硬體資訊與狀態、performance 和 events；腳本輸出需符合 Dell backend 接收格式。失敗時採 exponential backoff，在下一個 cycle 前重試；持續失敗的資料不會被放進送往 Dell backend 的 archive。

已確認：Helm ConfigMap、資料類型各有頻率、backend 相容格式、exponential backoff、失敗項目排除。待補：確切間隔、retry 上限／退避參數、資料 schema 與上送協定。

口頭講稿

以 iDRAC event 為例，Platform Service 接收底層 event 並記錄到 fault list，Event Manager 定期查詢並比對新增項目。之後依 mapping chart 組成 payload，包含 event ID、message、component、severity，以及需要的 node、cluster 或硬體位置資訊。系統會依 event 資訊辨識重複項目；throttling 則依 policy 間隔後再確認狀態，狀態仍符合條件才重新送出。事件可送到 vCenter；只有啟用 Dell backend 連線時才會再上送 Dell。

已確認：iDRAC → platform service → fault list → event manager → mapping chart → vCenter / 條件式 Dell backend；重複事件以 node、host、component 判斷；throttling 依 policy 等待後重新確認狀態，符合條件才再次送出。待補：policy 細節。

口頭講稿

原本安裝映像透過 iDRAC mount 的 OVA 複製到 storage，通常約需兩到三小時。我修改 NIM，讓它收到 file server 參數後選用高速 NIC、設定 NIC IP，並確認 file server 與 iDRAC NIC 可連通，再透過 file share 傳輸。Share 可由 NIM 啟動時建立，也可由工程師或客戶預先提供。連線驗證失敗時會顯示錯誤並停止，不會 fallback 到 iDRAC mount。改善後約 30 分鐘，實際時間仍取決於網路速度。

改善數字為約 2–3 小時降至 30 分鐘，實際時間受網路速度影響。

在 Amazon Alexa 團隊，我參與一個內部 AI 模型評估工具，負責前端和後端部分。使用者輸入 prompt、選擇 model，前端將該 model 的 ID 傳給後端，由後端呼叫相應 API 並回傳 response。Latency 定義為從送出 prompt 到完整 response 結束；token metric 記錄模型 response 的 token 數。資料依 model name 和 version 區分並送到 CloudWatch，圖表以時間為 X 軸、latency 或 token 數為 Y 軸，每個點代表一次 prompt，不同 model 用不同線呈現。

Latency 實際量測從 prompt 開始至完整 response 結束。若要補充串流體驗，可另量 TTFT（首 token 時間）。
